## Phase 1: SSO Authentication

The auth flow is SAML-based, cookie-driven. After SSO completes, the browser holds session cookies that authenticate all subsequent GraphQL calls.

### Step 1.1: HRD Discovery
```
POST https://us2.concursolutions.com/hrd/discoveries
Body: {
  "userName": "daoneill@redhat.com",
  "relayState": "<base64-encoded-relay-state>"
}
```
- `relayState` is base64 of: `{"state":"targetURL=%2Fhome&nuiflow=1","client_id":"4cb8cc62-a713-4a28-8ce0-4d96f78c9803","redirect_uri":"https://us2.concursolutions.com/nui/signin/setsession"}`
- **Dynamic**: relayState (but structure is static -- can be constructed)
- **Static**: client_id `4cb8cc62-a713-4a28-8ce0-4d96f78c9803` (verify next run)

### Step 1.2: SAML Request to Red Hat SSO
```
POST https://auth.redhat.com/auth/realms/EmployeeIDP/protocol/saml
Body: SAMLRequest=<base64-encoded-saml-request>
```
- **Dynamic**: SAMLRequest (generated by Concur)

### Step 1.3: Authenticate with Red Hat SSO
```
POST https://auth.redhat.com/auth/realms/EmployeeIDP/login-actions/authenticate
Body: username=daoneill&password=<password>&submit=Log+in+to+SSO
```
- **Dynamic**: password (from credential store)

### Step 1.4: SAML Response back to Concur
```
POST https://www-us.api.concursolutions.com/sso/saml2/V1/acs/
Body: SAMLResponse=<base64-encoded-response>
```
- **Dynamic**: SAMLResponse (generated by Red Hat SSO)

### Step 1.5: Set Session
```
POST https://us2.concursolutions.com/nui/signin/nui-auth/api/setsession
Body: lang=en-gb&no307=Y&passwordless=false&code=<auth-code>&state=<state>&correlationId=<correlation-id>&type=saml2
```
- **Dynamic**: code, correlationId
- Second call adds `ottcode=<token>` -- also dynamic

**Result**: Browser cookies set, all subsequent requests authenticated via cookies.

## Request Headers Pattern

All GraphQL requests use these headers:
```
Content-Type: application/json
Accept: */*
concur-correlationid: <uuid>
```

**No `Authorization` header** -- auth is entirely via cookies set during SSO.

Additional headers observed:
- `x-csrf-token` (on some requests)
- `x-nui` (NUI context)
- `x-referer` (internal routing)

## Existing MCP SSO Tools (for reuse investigation)

We already have SSO/SAML authentication tools in `tool_modules/aa_sso/src/tools_basic.py`.

### Browser-based SSO: `sso_authenticate`

```python
sso_authenticate(strategy="concur", headless=True)
```

- Already has a `"concur"` strategy in `KNOWN_STRATEGIES` (INLINE_REDIRECT flow)
- Uses Playwright to navigate -> SSO redirect -> fill credentials -> wait for redirect back
- Gets credentials from `get_sso_credentials()` (redhatter service on localhost:8009)
- After SSO completes, cookies are in the Playwright context
- **Could be used** to get authenticated cookies, then extract them for HTTP-only calls

### HTTP-only SAML: `http_saml_auth`

```python
http_session_create("concur", "https://us2.concursolutions.com")
http_saml_auth("concur", strategy="concur")
```

- Pure HTTP SAML flow (no browser needed) -- **currently only configured for `reward_zone`**
- 8-phase flow: init -> SAML login -> parse SSO form -> POST credentials -> extract SAMLResponse -> POST ACS -> set session
- **Concur is NOT yet added to `HTTP_SAML_CONFIGS`** -- code comment says "concur can be added later"
- The Concur SAML flow differs from Reward Zone (HRD discovery step, different ACS endpoint, `setsession` endpoint)

### HTTP Session Tools

```python
http_session_create(name, base_url)  # Create session with cookie jar
http_request(session, method, path, params, json_body)  # Make API calls
```

- Sessions persist cookies across requests (httpx.AsyncClient)
- Auto-injects `_csrf` token into POST/PUT/PATCH body
- **Perfect for GraphQL calls** once authenticated

### Helper: `get_sso_credentials`

- Fetches Red Hat SSO username/password from redhatter service (localhost:8009)
- Already used by Concur tools (`concur_get_sso_credentials`)

### Investigation Plan

**Option A: Hybrid (Browser SSO + HTTP GraphQL)**
1. Use `sso_authenticate("concur")` to get authenticated Playwright context
2. Extract cookies from browser context
3. Create `http_session_create("concur", ...)` and inject cookies
4. Make all GraphQL calls via `http_request`

**Option B: Pure HTTP (add Concur to `http_saml_auth`)**
1. Add `HTTPSAMLConfig` for Concur's SAML flow (HRD discovery, different ACS, setsession)
2. Authenticate entirely via HTTP
3. Make GraphQL calls via `http_request`

**Option B is preferred** (no browser dependency) but requires implementing Concur's unique SAML flow.
